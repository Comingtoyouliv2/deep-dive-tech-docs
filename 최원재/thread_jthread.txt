1. std::thread

class thread (c++ 11 이후)
이 쓰레드 클래스는, 한 개 쓰레드 실행을 나타냅니다. 쓰레드는 복수의 함수를 동시적으로 실행하는걸 도와줍니다. 
쓰레드는 쓰레드 객체 (OS 스케쥴링 지연에 좌우되지만)가 생성이되면 즉각적으로 실행되며, 생성자에 따라 바로 실행됩니다. 
가상 최상위 함수의 돌아오는 값은 무시되며, 예외가 발생한다면 std::terminate 를 부릅니다. 
최상위 함수는 자신의 리턴 값이나, 예외를 std::promise 를 통해 부르거나, 공유된 변수 값들을 수정하며 caller 와
상호작용합니다 (동기화가 필요하며, std::mutex, std::atomic 을 참고하세요)

std::thread 객체는 어떤 쓰레드도 대표하지 않는 상태에 있을 수도 있습니다 (기본 생성자, 이동, detach/join 이후). 
그리고, 쓰레드의 실행은 어떤 쓰레드와도 연관되어 있지 않을 수 있습니다 (detach 이후)

어떤 쓰레드 객체도, 같은 쓰레드 실행을 보여주지 않습니다.
std::thread 가 Move 로 생성/배정이 가능해도, 복사 생성/배정이 가능하지 않습니다.

3. std::mutex (c++11 이후)

class mutex 는, 동기화 관련 Primitive 이고, 공유되는 데이터가 여러 개의 쓰레드에 동시적으로 접근되는 것으로부터 보호한다.

mutex 는 배타적이고, 비-회귀적인 소유권적 의미를 제공합니다. 
unlock() 을 호출하기 전까지, lock, try_lock() 을 성공적으로 호출한다면, 그 쓰레드는 Mutex 를 소유하게 됩니다. 
쓰레드가 mutex 를 소유하는 순간부터, 모든 다른 쓰레드는 그 mutex 에 관한 소유권을 얻으려고 시도하는 순간부터 막혀질 것이고 (lock 함수로 인해), 그리고
try_lock() 으로부터 false 값을 받습니다.
쓰레드는 lock 혹은 try_lock 을 부르기 전까지 mutex 를 소유하지 않습니다. 

mutex 가 다른 쓰레드에게 소유되고 있는 상태에서 파괴되거나, 쓰레드가 mutx 를 소유하고 있는 동안 terminate 되면, 그 프로그램의 행동은 정의되지 않습니다.
Mutex 클래스는 Mutex, StandardLayoutType 의 모든 요구사항을 충족합니다. 

std::mutex 그 자체는 복사, 이동이 불가능합니다.


4. std::lock_guard(C++11 이후)
template <class Mutex>
class lock_guard;

-> mutex 가 
lock_guard 클래스는, mutex wrapper 로서, RAII 스타일 
lock_guard 객체가 형성되면, mutex 의 소유권을 가져오기 위한 시도를 합니다. 통제하려는 범위 밖으로 벗어난다면,
lock_guard 는 파괴되고, mutex 는 해제됩니다. 

lock_guard 는 복사 불가능합니다.
